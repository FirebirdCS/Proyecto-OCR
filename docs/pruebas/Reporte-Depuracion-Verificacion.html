2. SCRUM-112 · Mensajes de error en inglés en el panel de administración

2.1 Ficha

2.2 Pasos para reproducir

  1. Iniciar sesión como administrador.
  2. Campañas: crear una campaña en borrador sin productos ni hitos y elegir Activar.
  3. Productos: eliminar un producto que use una campaña en borrador o activa (por ejemplo, Paracetamol).
  4. Usuarios: crear una cuenta con un correo que ya está registrado.

2.3 Análisis de causa raíz

  • El cliente muestra el texto del servidor tal cual. client/src/services/api.ts crea el error con payload.error, y cada panel de administración hace setError(cause.message). Los textos en español de esos paneles solo aparecen cuando la respuesta no trae mensaje.
  • El servidor redactaba todos sus mensajes en inglés: los HttpError de 15 archivos y los mensajes de las reglas de campaña en types/campaigns.ts.
  • Los errores de validación (Zod) se respondían siempre como «Validation failed». El detalle iba en details, que la pantalla no muestra, así que el administrador no sabía qué campo corregir.
  • Por qué no se detectó antes: la pantalla del escáner (rol Usuario) no tiene el problema, porque traduce por código (duplicate_receipt, daily_limit…) con la tabla REFUSALS de UserDashboard.tsx. El panel de administración nunca recibió ese tratamiento. Además, los formularios bloquean la mayoría de los datos inválidos antes de enviarlos, así que el mensaje de validación casi nunca se veía.

2.4 Corrección aplicada

Se tradujeron los mensajes en el servidor, que es donde se originan. La otra opción era traducir en cada pantalla por código, pero la API solo tiene este cliente, que es en español: corregir en el servidor arregla todas las pantallas a la vez, incluidas las futuras. Los códigos de error para el escáner no cambian, así que su pantalla sigue funcionando igual.

ArchivoCambio
server/src/utils/validationMessage.tsNuevo. Redacta en español el primer problema de una validación fallida, a partir del código del problema (campo vacío, mínimo, máximo, correo, fecha, entero…) y una tabla de nombres de campo.
server/src/middleware/errorHandler.tsUn error de validación ya no responde «Validation failed»: responde «Datos no válidos: …» con la frase de arriba. También se tradujeron «Not found», «Internal server error» y el aviso de índice faltante.

server/src/services/campaigns.service.tsCampaña no encontrada, archivada de solo lectura, no se puede activar, archivar antes de eliminar, productos desconocidos o desactivados.
server/src/services/products.service.tsProducto no encontrado y «La campaña «X» todavía usa este producto…».
server/src/services/users.service.tsCorreo que ya tiene cuenta, quitarse el propio rol, deshabilitar la propia cuenta, cuenta sin correo.
server/src/services/scoring.service.tsComprobante no encontrado, ya anulado, sin puntos, duplicado, límite diario, no participante, campaña no vigente (los códigos para la pantalla del escáner no cambian).

Otros 7 archivosdocuments, credentials, mail, resend, receiptFiles, mail.routes y las rutas de comprobantes y OCR: un mensaje cada uno.

En total, 15 archivos modificados y 1 nuevo: 48 líneas añadidas y 47 eliminadas, más el archivo nuevo. No cambia ningún código de estado HTTP ni ninguna regla de negocio; solo el texto.

Fuera de alcance, a propósito. Tres mensajes siguen en inglés porque corresponden a otros bugs de la lista, cada uno con su propia causa:
  • «Expected a file upload…» al subir un tipo de archivo no admitido (bug 2).
  • El error 500 con un archivo de más de 10 MB (bug 3).
  • «Vision API error: …» cuando falla Cloud Vision (bug 6).
Se corrigen por separado para que cada uno tenga su verificación.
